# 微信小程序点餐系统 - 产品说明

## 1. 项目定位

本项目是一套面向单个蛋挞摊位的二维码点餐系统。

顾客通过微信扫描二维码进入小程序，浏览蛋挞商品、选择普通商品或套餐、加入购物车、提交订单并完成支付；摊主通过管理端查看订单、维护商品和库存、更新订单制作状态。

V1.0 明确定位为**单摊位、轻量级、可实际运行**的点餐系统，不做多门店、多摊位平台化设计。

## 2. 核心目标

1. 顾客能够快速完成自助点餐。
2. 摊主能够快速查看和处理订单。
3. 库存能够在并发下保持正确，避免超卖。
4. 订单、支付、库存状态保持一致。
5. 保留后续接入真实微信支付和扩展业务的空间。
6. 通过完整项目实践掌握需求、设计、开发、测试、部署和上线流程。

- 商品详情

- 库存维护
- 订单查看
- 订单状态处理
- 基础经营概览

## 4. 商品模型

商品分为：

- `single`：普通商品
- `combo`：套餐

示例：

- 原味蛋挞 ¥4
- 芝士蛋挞 ¥5
- 芋泥蛋挞 ¥6
- 6个蛋挞任选 ¥25

套餐不拥有独立库存，套餐中的选择会消耗对应普通商品库存。

## 5. 核心业务原则

- 前端展示价格不是最终价格，后端必须重新读取数据库价格。
- 前端提交的用户身份不能直接作为授权依据。
- 库存扣减必须由数据库原子操作保证并发安全。
- 订单创建、库存处理、订单明细和支付记录必须通过数据库事务保证一致性。
- 历史订单保存商品名称、单价和套餐选择快照，不依赖商品当前数据。
- 订单状态和支付状态分开管理。
- 待支付订单取消或超时后，应释放已经扣减/预占的库存。

## 6. V1.0 明确不做

- 多门店/多摊位
- 会员
- 手机号登录
- 密码登录
- 积分
- 优惠券
- 拼团
- 配送
- 地址管理
- 复杂 SKU / 多规格
- 营销活动
- 复杂财务报表
- 多角色复杂权限
- 推荐、收藏、评价
- 消息中心

## 7. 成功标准

顾客可以从微信小程序完成：

登录 → 浏览商品 → 购物车 → 提交订单 → Mock 支付 → 查看订单。

管理员可以完成：

登录 → 商品/分类维护 → 库存维护 → 查看订单 → 制作中 → 已完成。

系统在两个用户并发购买最后库存时，只允许库存充足的一方成功，不产生超卖。
