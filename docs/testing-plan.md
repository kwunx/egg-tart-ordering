# 测试计划

## 1. 测试目标

验证：

- 功能正确
- 数据一致
- 并发安全
- 权限正确
- 异常可恢复

## 2. 功能测试

### 登录

- 正常 code
- 无效 code
- 重复登录
- Token 失效

### 商品

- 正常查询
- 商品下架
- 分类筛选
- 库存为 0

### 订单

- 正常创建
- 商品不存在
- 商品已下架
- 数量非法
- 库存不足
- 金额计算

### 套餐

- 0/6
- 4/6
- 5/6
- 6/6
- 7/6
- 选择不允许的商品
- 选择库存不足商品

## 3. 安全测试

### 价格篡改

前端发送：

```json
{
  "product_id": 1,
  "price": 0.01
}
```

服务器必须忽略前端价格。

### 订单越权

用户 A 请求用户 B 的订单。

必须拒绝。

### 状态篡改

客户端尝试把订单直接改为：

```text
completed
```

必须拒绝。

## 4. 并发测试

库存 = 1。

同时发送多个购买请求。

期望：

```text
成功 = 1
失败 = 其余全部
最终库存 = 0
```

## 5. 事务测试

故意让订单创建过程中某一步失败。

期望：

```text
库存恢复
订单不存在
订单明细不存在
支付记录不存在
```

即事务完全回滚。

## 6. 取消测试

第一次取消：

```text
成功
库存恢复
```

第二次取消：

```text
不重复恢复库存
```

## 7. 支付测试

- 正常支付
- 重复支付
- 支付失败
- 已取消订单不能支付
- 已支付订单不能重复支付

## 8. 状态机测试

允许：

```text
pending_payment → paid
paid → making
making → completed
```

拒绝：

```text
completed → making
cancelled → paid
completed → pending_payment
```

## 9. API 测试

使用 pytest + FastAPI TestClient/HTTP 客户端测试核心接口。

重点覆盖：

- auth
- products
- orders
- payments
- admin
